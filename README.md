# GIF to PNG API

Курсовая работа по разработке веб-приложения с HTTP API для асинхронного преобразования изображений из формата GIF в PNG.

**Вариант №3.**

Проект реализован на Python и включает консольный конвертер изображений, HTTP API, асинхронную обработку задач, реляционную базу данных SQLite и автоматизированное тестирование.

## Технологии

- Python 3.11
- Pillow — обработка изображений
- `http.server` — HTTP-сервер
- XML — формат запросов и ответов API
- HTTP Basic Authentication — авторизация
- `threading` и `subprocess` — асинхронное выполнение задач
- SQLite — реляционная база данных
- SQLAlchemy — объектно-реляционное отображение (ORM)
- pytest — автоматизированное тестирование
- Hypothesis — генерация тестовых сценариев и Model-Based Testing
- coverage.py — анализ покрытия кода тестами

## Этап 1. Консольная утилита

Разработана консольная программа для преобразования GIF-изображений в PNG.

### Возможности

- Чтение путей к файлам через стандартный ввод.
- Преобразование GIF в PNG с помощью Pillow.
- Сохранение PNG-файлов на диск.
- Обработка ошибок входных данных.
- Поддержка прозрачности изображений.
- Преобразование первого кадра анимированного GIF.

### Запуск конвертера

```powershell
python -m src.converter
```

Программа последовательно запрашивает путь к исходному GIF-файлу и путь для сохранения PNG.

### Генерация примеров

```powershell
python examples/generate_examples.py
```

## Этап 2. HTTP API

Реализован HTTP API на основе `BaseHTTPRequestHandler` и `ThreadingHTTPServer`.

API поддерживает:

- HTTP-методы GET, POST и PATCH.
- Передачу параметров через строку запроса и путь.
- XML-тела запросов для изменения записей.
- XML-ответы сервера.
- Авторизацию HTTP Basic Authentication.
- Создание и изменение сессий.
- Создание и изменение инструкций преобразования.
- Асинхронную обработку задач через `threading` и `subprocess`.
- Получение информации о результатах преобразования.
- Формирование отчётов.

### Маршруты HTTP API

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/session-add` | Создание сессии |
| GET | `/api/session-scan` | Получение списка сессий |
| GET | `/api/session-single` | Получение сессии по ID |
| PATCH | `/api/session-edit/:id` | Изменение сессии |
| POST | `/api/instruction-add` | Создание инструкции |
| GET | `/api/instruction-scan/:session` | Список инструкций сессии |
| GET | `/api/instruction-single` | Получение инструкции по ID |
| PATCH | `/api/instruction-edit/:id` | Изменение инструкции |
| GET | `/api/completion-scan/:instruction` | Список результатов инструкции |
| GET | `/api/completion-single` | Получение результата по ID |
| GET | `/api/report-scan` | Формирование отчёта |

Дополнительно реализован маршрут `GET /api/health` для проверки работоспособности сервера.

### Асинхронное преобразование

При создании инструкции сервер регистрирует задачу и запускает фоновый поток обработки.

Фоновый обработчик вызывает консольный конвертер через `subprocess`.

Задача может находиться в одном из следующих состояний:

- `pending` — ожидает выполнения;
- `running` — выполняется;
- `completed` — успешно завершена;
- `failed` — завершилась с ошибкой.

Информация о выполнении сохраняется в таблице Completion.

### API-клиент

В проекте реализован Python-клиент `APIClient`, позволяющий обращаться к HTTP API программно.

## Этап 3. SQLite и SQLAlchemy

Реализован постоянный слой хранения данных на основе реляционной СУБД SQLite.

Для работы с базой данных используется ORM SQLAlchemy.

### Структура базы данных

В базе данных предусмотрены три связанные таблицы.

**Session**

Хранит информацию о пользовательских сессиях:

- `id`
- `timestamp`
- `locale`
- `user_agent`

**Instruction**

Хранит инструкции преобразования:

- `id`
- `timestamp`
- `argument`
- `session`
- `tags`

**Completion**

Хранит результаты выполнения инструкций:

- `id`
- `timestamp`
- `result`
- `stage`
- `failure`
- `instruction`
- `cache_hit`
- `duration`

Связи между таблицами реализованы с использованием внешних ключей.

### Возможности SQLite-хранилища

- Создание записей.
- Получение отдельных записей.
- Поиск и получение списков записей.
- Изменение существующих записей.
- Сохранение данных между перезапусками приложения.
- Поддержка связей между таблицами.
- Формирование отчётов с использованием SQL-запросов.

HTTP API использует `SQLiteStorage` в качестве постоянного хранилища данных.

### Формирование отчёта

Маршрут `/api/report-scan` формирует отчёт по инструкциям за последние шесть минут.

В отчёт включаются:

- продолжительность выполнения (`duration`);
- результат преобразования (`result`);
- теги инструкции (`tags`).

Для формирования отчёта используются данные связанных таблиц Instruction и Completion.

## Запуск HTTP-сервера

```powershell
python -m src.api.server --username admin --password admin123
```

По умолчанию сервер запускается по адресу:

`http://127.0.0.1:8765`

При необходимости можно указать адрес и порт через параметры `--host` и `--port`.

Для запуска без реального преобразования файлов предусмотрен тестовый режим:

```powershell
python -m src.api.server --username admin --password admin123 --test-mode
```

Указанные учётные данные приведены только для локального примера запуска.

### Пример HTTP-запроса

Создание новой сессии:

```powershell
curl.exe -i -u admin:admin123 -X POST "http://127.0.0.1:8765/api/session-add?locale=ru&user_agent=VSCode"
```

Получение списка сессий:

```powershell
curl.exe -i -u admin:admin123 "http://127.0.0.1:8765/api/session-scan"
```

Получение сессии по идентификатору:

```powershell
curl.exe -i -u admin:admin123 "http://127.0.0.1:8765/api/session-single?id=1"
```

## Автоматизированное тестирование

В проекте используются pytest, Hypothesis и coverage.py.

Реализованы:

- Модульные тесты конвертера GIF → PNG.
- Тесты операций хранилища в памяти.
- Тесты SQLite-хранилища.
- Тесты HTTP API.
- Проверки авторизации и обработки ошибок.
- Тесты фонового обработчика преобразований.
- Model-Based Testing HTTP API с использованием Hypothesis.
- Stateful-тестирование HTTP API с SQLite.

### Запуск всех тестов

```powershell
python -m pytest -q
```

### Stateful-тестирование HTTP API с SQLite

```powershell
python -m pytest tests/test_api_sqlite_stateful.py -v
```

### Проверка покрытия кода

```powershell
python -m coverage erase
python -m coverage run --branch -m pytest
python -m coverage report -m
```

Генерация HTML-отчёта:

```powershell
python -m coverage html
start htmlcov/index.html
```
